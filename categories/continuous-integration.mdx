Continuous integration (CI) workflows run automatically on push and pull request events to build your code and run your test suite. The starter templates in this category give you a pre-configured workflow for your language's toolchain — package manager, test runner, and matrix of runtime versions — so you can be confident each pull request passes before it merges.

<Tip>
  GitHub suggests the most relevant templates automatically based on your
  repository's detected language.
</Tip>

## Example: Node.js CI

The `node.js.yml` template runs your build and test suite across Node.js 18, 20, and 22 using a matrix strategy, caching npm dependencies between runs.

<Accordion title="node.js.yml — full workflow">
```yaml
# This workflow will do a clean installation of node dependencies, cache/restore them, build the source code and run tests across different versions of node
# For more information see: https://docs.github.com/en/actions/automating-builds-and-tests/building-and-testing-nodejs

name: Node.js CI

on:
  push:
    branches: [ $default-branch ]
  pull_request:
    branches: [ $default-branch ]

jobs:
  build:

    runs-on: ubuntu-latest

    strategy:
      matrix:
        node-version: [18.x, 20.x, 22.x]
        # See supported Node.js release schedule at https://nodejs.org/en/about/releases/

    steps:
    - uses: actions/checkout@v4
    - name: Use Node.js ${{ matrix.node-version }}
      uses: actions/setup-node@v4
      with:
        node-version: ${{ matrix.node-version }}
        cache: 'npm'
    - run: npm ci
    - run: npm run build --if-present
    - run: npm test
```
</Accordion>

Key points in the template:

- **Matrix strategy** — runs one job per Node.js version in parallel, so you catch version-specific regressions immediately.
- **`cache: 'npm'`** — restores the npm cache between runs to keep install times short.
- **`npm run build --if-present`** — runs the build script only when it exists, so the template works for projects without an explicit build step.
- **`$default-branch`** — a placeholder that GitHub replaces with your repository's default branch name when you add the workflow.
