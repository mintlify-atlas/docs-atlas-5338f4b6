---
title: "Quickstart"
description: "Add a Node.js CI workflow to your repository using a starter workflow template."
---

This guide walks you through adding the Node.js CI starter workflow to a repository. The same steps apply to any other template in the library.

<Steps>
  <Step title="Open the Actions tab">
    Navigate to your GitHub repository and click the **Actions** tab. If your repository already contains workflow files, click **New workflow** to reach the template picker.

    GitHub detects your repository's language and tech stack, and surfaces matching templates at the top of the list. For a Node.js project, the **Node.js** template will appear in the suggested section.
  </Step>

  <Step title="Select the Node.js template">
    Find the **Node.js** template — described as "Build and test a Node.js project with npm" — and click **Configure**.

    GitHub opens an inline editor pre-filled with the workflow YAML shown below:

    ```yaml
    # This workflow will do a clean installation of node dependencies, cache/restore them,
    # build the source code and run tests across different versions of node
    # For more information see: https://docs.github.com/en/actions/automating-builds-and-tests/building-and-testing-nodejs

    name: Node.js CI

    on:
      push:
        branches: [ $default-branch ]
      pull_request:
        branches: [ $default-branch ]

    jobs:
      build:

        runs-on: ubuntu-latest

        strategy:
          matrix:
            node-version: [18.x, 20.x, 22.x]
            # See supported Node.js release schedule at https://nodejs.org/en/about/releases/

        steps:
        - uses: actions/checkout@v4
        - name: Use Node.js ${{ matrix.node-version }}
          uses: actions/setup-node@v4
          with:
            node-version: ${{ matrix.node-version }}
            cache: 'npm'
        - run: npm ci
        - run: npm run build --if-present
        - run: npm test
    ```

    <Note>
      The `$default-branch` placeholder is not literal YAML — GitHub substitutes it with your repository's actual default branch name (typically `main` or `master`) at the moment you commit the file. You will see the resolved branch name in the committed workflow file.
    </Note>
  </Step>

  <Step title="Understand the properties file">
    Behind the scenes, every template has a corresponding `properties.json` file that controls what you see in the template picker UI. For the Node.js template, that file looks like this:

    ```json
    {
        "name": "Node.js",
        "description": "Build and test a Node.js project with npm.",
        "iconName": "nodejs",
        "categories": ["Continuous integration", "JavaScript", "npm", "React", "Angular", "Vue"]
    }
    ```

    The `categories` array is what causes this template to surface when GitHub detects JavaScript, npm, React, Angular, or Vue in your repository.
  </Step>

  <Step title="Review and adjust the workflow">
    The template runs your build and tests against Node.js versions 18, 20, and 22 in parallel using a build matrix. Before committing, consider whether you need to:

    - Narrow the `node-version` matrix to only the versions your project supports.
    - Add environment variables required by your test suite.
    - Adjust the `npm run build --if-present` step if your project uses a different build script name.

    <Tip>
      The `--if-present` flag on `npm run build` means the step is skipped silently if your `package.json` does not define a `build` script. You do not need to remove that line for projects without a build step.
    </Tip>
  </Step>

  <Step title="Commit the workflow file">
    When you are satisfied with the workflow, click **Commit changes**. GitHub saves the file to `.github/workflows/node.js.yml` in your repository (on the branch you choose — typically your default branch).
  </Step>

  <Step title="Watch your first run">
    Because the workflow triggers on `push` to your default branch, committing the file immediately queues a run. Go back to the **Actions** tab to watch it execute.

    You will see three parallel jobs — one for each Node.js version in the matrix — each running `npm ci`, `npm run build`, and `npm test`. A green checkmark on all three means your project builds and passes tests on every supported Node.js version.
  </Step>
</Steps>
